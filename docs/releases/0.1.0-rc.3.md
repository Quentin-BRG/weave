# Weave 0.1.0-rc.3

This release candidate supports stopping Weave, using ordinary Git on the same
branch, and resuming the same collaborative session. Pulls, direct commits,
rebases and rewinds are reconciled with preserved collaborative work. Overlapping
changes create explicit Weave conflicts, with recovery copies of the candidates.

## Upgrade together

- Upgrade the host and every participant to this build. Application protocol 4
  requires matching peers; encryption and the Noise transport remain mandatory.
- Existing rc.2 session databases are backed up and migrated under the daemon
  lock. Older binaries cannot open the migrated databases. Keep the recovery
  archives; do not downgrade an active migrated checkout.
- Old encrypted invitations remain readable. Admission negotiates the host's
  actual current Git commit; new invitations no longer include a commit.
- Update the agent skills to weave-plugin 1.1.0-rc.1 alongside this CLI.

## Session and connection changes

- `stop` and Ctrl+C preserve the session. `leave` also works while stopped,
  archives local state, and confirms durable departure before reporting success.
- Status distinguishes saved sessions, daemon state, transport, admission and
  complete synchronization. Unknown daemon state is an error, not permission to
  perform raw Git writes.
- Encrypted heartbeats expire silent connections after 15 seconds. LAN resume
  reuses the previous port when available. `weave invite refresh` updates the LAN
  address; share the new invitation manually with participants, who can use
  `weave join` without losing their outbox or recreating the session.
- Joining receives verified Git objects from the host. Local commits receive
  recovery references. `--local-changes=backup|discard|cancel` controls affected
  local work; backup keeps it separate from collaboration.
- `weave recover --list` and `weave recover --backup <id> --export <new-directory>`
  expose recovery archives, including index blobs and uncommitted files.
- Shared exclusions follow the canonical `.gitignore` rules while retaining
  already tracked files. Exclusion preserves local files. Per-path errors block
  complete-sync claims and ambiguous publications without stopping other files.
- Git identities are refreshed when preparing and creating publications.

Changing branches still requires a new session. Git writes while Weave is active
pause collaboration; stop and resume for controlled adoption. See
[session reliability and recovery](https://github.com/Quentin-BRG/weave/blob/v0.1.0-rc.3/docs/SESSION-RELIABILITY.md) for the full behavior.
