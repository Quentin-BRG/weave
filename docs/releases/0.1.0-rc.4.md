# Weave 0.1.0-rc.4

This release fixes synchronization stalls when resuming a participant with old
pending files that the session now excludes, notably `node_modules`.

- Each excluded pending path now saves only its replica state, local versions,
  associated conflict metadata and referenced blobs. It no longer copies the
  entire session for every excluded dependency. Pending operations are detached
  only after their recovery archive is durable. Local files stay on disk.
- Large Git input/output batches are drained concurrently. A burst of ignored
  filesystem events can no longer deadlock `git check-ignore` and freeze the
  replica engine. Git failures retain their own diagnostics.
- A local control timeout now says that the daemon did not respond and may be
  busy or blocked, instead of presenting it as a filesystem error. Its state
  remains unknown; the CLI never reports a stopped daemon from this timeout.
- Installation diagnostics use the running executable's package. An unrelated
  system installation can no longer hide a broken portable package or cause a
  source build to identify itself as the installed package.

Protocol 4 and the existing session schema are unchanged. Existing archives,
including large rc.3 backups, remain available through `weave recover --list`
and `weave recover --backup <id> --export <new-directory>`; this update does not
delete them. The current weave-plugin 1.1.0-rc.1 remains compatible.

Stop Weave, install this version on the host and participants, then use
`weave resume`. Keep `.git/weave` and the working files: removing session state
or resetting Git is not part of this upgrade. If stop cannot complete because a
daemon is still blocked, diagnose that process before resuming; an IPC timeout
does not establish that it has exited.
